# Med Security Checklist (Pre-Production Review)

> **CRITICAL MANDATE:** Before entering any real, identifiable medical or personal health data, you must review and verify every item on this checklist.

---

## 1. Database & Row Level Security (RLS)

- [ ] **Default Deny Verified:** Confirm that `ENABLE ROW LEVEL SECURITY` is executed on every table (`families`, `family_members`, `people`, `emergency_contacts`, `viewer_grants`, `consents`, `audit_log`).
- [ ] **Cross-Family Isolation:** Verify that no user in Family A can query rows belonging to Family B (proven by `src/lib/family/__tests__/rls.test.ts`).
- [ ] **Manager vs Viewer Permissions:** Confirm that members with role `viewer` cannot INSERT, UPDATE, or DELETE any records, and can only SELECT records where an active, unexpired, and unrevoked `viewer_grant` exists.
- [ ] **Audit Log Immutability:** Verify that the trigger `trg_prevent_family_audit_log_mutation` is active and prevents any UPDATE or DELETE operations on `public.audit_log`.
- [ ] **Zero Health Data in Logs:** Verify that application loggers and `audit_log.metadata` sanitize all payloads and never store allergies, chronic conditions, notes, blood types, or clinical values (proven by `src/lib/family/__tests__/audit.test.ts`).

---

## 2. Authentication & Access Control

- [ ] **Clinic Gateway Isolation:** Ensure the clinic login stub does not allow public registration and that staff roles (`manager`, `doctor`, `receptionist`) can only be provisioned via verified invitation tokens.
- [ ] **Consent Gating:** Confirm that unconsented users are blocked from viewing or entering family data until they explicitly review and sign the medical non-diagnostic disclaimer.
- [ ] **Rate Limiting:** Ensure rate limiting is active on auth routes (`/api/auth/*` and `/api/family/*`) to protect against brute-force credential stuffing.
- [ ] **HTTPS Enforced:** Confirm that `Strict-Transport-Security` (HSTS) is enabled and all HTTP traffic is redirected to HTTPS with TLS 1.3.

---

## 3. Storage & Document Privacy

- [ ] **Private Storage Bucket:** Confirm that bucket `family_documents_private` is set to `public = FALSE`.
- [ ] **Signed URLs Only:** Verify that files can only be accessed via short-lived cryptographically signed URLs (expiring in 15–60 minutes) generated by authorized server actions.
- [ ] **File Size & MIME Whitelist:** Ensure uploaded documents are restricted to PDF, JPEG, PNG, and WebP, with file sizes capped at 10MB.

---

## 4. User Data Control & Deletion Rights

- [ ] **Open Data Export:** Test that "تصدير بياناتي (JSON)" produces clean, machine-readable JSON containing all family health records without platform lock-in.
- [ ] **Soft vs Hard Deletion:** Verify that standard deletion of a family member sets `archived_at` to preserve clinical history, while "Delete all my data" permanently purges records only after explicit typed confirmation.
